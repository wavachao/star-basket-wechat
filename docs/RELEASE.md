# 微信小游戏首发操作指南

本项目已按微信小游戏结构准备，账号上传与正式上线仍依赖实际运营者的微信登录、真实 AppID、后台资料及平台审核。不要把浏览器通过、模拟器运行、代码上传或体验版当作正式上线。

## 1. 准备自己的账号

1. 在 [微信公众平台](https://mp.weixin.qq.com/) 注册或登录小游戏账号，确认服务类型为小游戏，并确认主体信息与实际运营者一致。
2. 在后台获取小游戏 AppID，将负责操作的微信添加为开发者或管理员。
3. 下载并登录 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
4. 在后台逐项核对小游戏备案、主体认证、类目、游戏资质、隐私保护指引、名称及内容要求。平台要求的材料由实际主体提供。本项目不提供版号、软件著作权、备案号、实名认证或防沉迷资质。

**规则核验状态（2026-10-02）：** 已尝试读取微信官方开发与配置文档，但当前检索环境无法打开正文。此指南给出操作流程，不宣称个人主体、免费玩法或无服务器一定免除任何资质。发布条件与具体材料清单必须以登录后的官方后台当前提示为准，不能用第三方旧教程替代。

官方入口：[小游戏开发文档](https://developers.weixin.qq.com/minigame/dev/guide/)、[微信公众平台](https://mp.weixin.qq.com/)。

本工作站已将微信官方稳定版工具安装到项目的 `.tools/wechat-devtools`，安装包腾讯数字签名验证通过。打开其中的 `微信开发者工具.exe`，用管理员微信扫码登录，并在“设置 → 安全设置”开启“服务端口”，即可使用本项目封装的命令：

```powershell
npm run wechat -- status
npm run wechat -- open
npm run wechat -- preview
npm run wechat -- upload
```

`open` 导入当前构建后的 `dist/wechat`，`preview` 生成 `artifacts/wechat-preview.png` 供扫码真机游玩，`upload` 上传版本 1.0.0。没有管理员登录或项目权限时，微信工具会拒绝操作；服务端口关闭时无法用命令行控制工具。也可以在开发者工具界面手动导入、预览、上传。其他电脑需要自行安装官方工具，或设置 `WECHAT_DEVTOOLS` 为其安装目录。

## 2. 构建真正的微信项目

在项目目录执行：

```powershell
npm run test
npm run check
npm run build -- --appid wx2c7a7dc88ff120e5
```

只导入 `dist/wechat`。该目录包含 `game.js`、`game.json`、`project.config.json`、`src/` 以及存在时的 `assets/`。文档、测试、开发工具和浏览器页面不会进入代码包。

不指定 AppID 时使用源配置中的 `wx2c7a7dc88ff120e5`，这是用户提供的 AppID。实际微信工具导入返回 code 10：“AppID 不是小程序/小游戏类型”，因此该 ID 目前不可用于小游戏上传，必须在小游戏后台核对并替换为有效小游戏 AppID。`touristappid` 可用于本地预览，但不能用于正式上传。网络域名校验保持开启。

开发者工具导入路径选择 `dist/wechat`，检查项目类型为小游戏、AppID 正确。若工具提示基础库兼容性，选当前稳定基础库，并在实机确认，勿仅凭模拟器结果。

## 3. 真机验收记录

建议至少记录一台 Android 与一台 iPhone 的实际结果；没有设备时标记“未验证”，不要填写通过。

| 验收项目 | 操作及预期 | 实测结果 |
| --- | --- | --- |
| 首屏 | 打开后看到名称、玩法和开始按钮，无空白、报错 | 待实机填写 |
| 操作 | 左右拖动，篮子跟手且不越界；单指触摸正常 | 待实机填写 |
| 得分 | 星星接住后加分，石头扣心，结果页分数正确 | 待实机填写 |
| 回合结束 | 60 秒结束或心用完进入结算，重玩清零当前局 | 待实机填写 |
| 暂停 | 暂停时不计时；继续恢复；切后台后再回到游戏 | 待实机填写 |
| 本地存储 | 最高分和音效选择在重新打开后保留 | 待实机填写 |
| 音效 | 首次操作后音效可用，关闭后安静 | 待实机填写 |
| 屏幕适配 | 刘海、窄屏、长屏上的按钮和 HUD 可见可点 | 待实机填写 |
| 稳定性 | 连续完成五局，游戏始终可继续游玩 | 待实机填写 |

在开发者工具点击“预览”，用有权限的微信扫码。遇到报错先查看控制台与真机调试记录。若音频在浏览器首次点击前无声属于浏览器限制；实机音频结果需另外确认。

## 4. 准备后台材料

使用 `docs/STORE.md` 中的名称、简介、玩法和自审草稿；使用项目生成的图标与实际游戏截图。名称是否可用、图标尺寸、截图数量及格式遵循后台当时显示的要求。

`docs/PRIVACY.md` 是对代码数据行为的说明草稿。填入实际运营主体、有效联系方式与生效日期，核对后台隐私保护配置，再发布正式声明。不要将未填信息或虚构联系方式提交给用户。

自审报告中的代码功能描述可以复用，署名、日期、资质及实机结果必须据实填写。完成后台要求的资质、备案、服务类目与隐私配置，保存提交回执。

## 5. 上传、提审与发布

1. 开发者工具确认使用真实 AppID，点击“上传”；首版建议版本号 `1.0.0`，备注“接住小星星首版：竖屏单机接星星、避石头、60 秒回合、本地最高分、音效开关”。
2. 在公众平台的版本管理查看开发版本，确认版本号与上传时间；按需设为体验版，邀请实际测试人员。
3. 复核后台全部待办项，选择提交审核，填写简介、玩法、功能页面与要求的材料。游戏无登录，不需要虚构测试账号。
4. 如果被驳回，保留原文及截图，按具体问题修复代码或材料，重新上传新版本，再次提交。不要预测或承诺审核时长。
5. 审核通过后，由管理员在后台执行发布并确认正式版状态。用其他微信账号通过实际入口打开，完整游玩一局并重玩。

正式上线的证据应包括后台已发布状态、实际可访问入口或二维码以及外部账号真机游玩结果。无这些证据时，只能报告“已构建”“已上传”或“待审核”等实际状态。

## 6. 发布后更新

保留已发布版本对应的 Git 提交。修改后运行测试与检查，重新构建、真机验证，以 `1.0.1` 等新版本上传并重复审核/发布流程。仅切换代码目录不会更新线上游戏。
